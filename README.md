# Atelier DIY — static site

Six pages, built from two sources, and — since the client's scoping note —
styled as **two deliberately separate halves**:

| Half | Pages | Design |
|---|---|---|
| **Replica** | `index`, `hoe-werkt-het`, `realisaties`, `tutorials` | A faithful rebuild of `staging.diy-atelier.be`. Poppins, `#fd8b11`, rounded corners. **No brand layer.** |
| **Brandbook** | `webshop`, `product` | The SETT brandbook build. `assets/brand.css`, the 02.01 palette, PT Serif / Franklin / Avenir, hard edges, the book's own compositions. |

An earlier round applied the brand layer to all six and traded the replica's
pixel fidelity for brandbook fidelity. The client scoped that back: **only the
webshop and the product page are to be redesigned.** The four replica pages are
byte-identical to the last commit and do not load `assets/brand.css` at all.

The seam is visible and intended — chiefly in the header, where the replica half
keeps the orange wordmark and orange active-nav and the brandbook half carries
the 01.03 lockup in black. `build.py` emits both from one `header()` so the
**navigation itself** can never drift; see "The chrome is shared, the skin is
not".

> If the two halves are meant to converge later, the move is to add the
> `assets/brand.css` link to the four replica pages — one `<link>` per page in
> `build.py`'s `page()`. Most of what those pages would need is still in the
> file; see "What is dead in `brand.css` now".

## Pages

Only `webshop.html` and `product.html` load `assets/brand.css`, and they load it

| File | Screen | Layout stylesheet | Brand layer | Source |
|---|---|---|---|---|
| `index.html` | Overzicht (homepage) | `site.css` | — | generated by `build.py` |

| `realisaties.html` | Realisaties | `site.css` | — | generated by `build.py` |
| `tutorials.html` | Tutorials | `site.css` | — | generated by `build.py` |
| `webshop.html` | Catalogue — 33 pakketten | `app.css` + `chrome.css` | `brand.css` | body hand-authored, chrome generated |
| `product.html` | Product detail (`?id=`) | `app.css` + `chrome.css` | `brand.css` | body hand-authored, chrome generated |

`build.py` writes the four replica pages whole. For `webshop.html` and
`product.html` it only rewrites the header and footer, in place, between these
markers:

```html
<!-- chrome:header -->  …generated…  <!-- /chrome:header -->
<!-- chrome:footer -->  …generated…  <!-- /chrome:footer -->
```

Everything outside the markers is left alone, so the catalogue bodies stay
hand-authored while the chrome can never drift from the replica pages. Re-run
`python build.py` after any change to `NAV`, `header()` or `FOOTER`. The sync is
idempotent — running it twice is a no-op.

**Both catalogue pages carry the shared chrome now.** `product.html` used to
keep the old 72px header with no burger, so below 900px its navigation was
simply absent and the logo was the only way out. It is on `sync_chrome` like the
webshop.

## The SETT brand layer — `assets/brand.css`

The client's brief has come in three rounds.

1. The **logo-icoon (01.03)** was missing.
2. The brandbook should be reflected *more specifically still*, with the visual
   design free to change completely as long as it tracks the book — and,
   explicitly, **"don't overuse the logo-icoon."**
3. **Both catalogue pages get another pass**, going further again.

Round 1 answered the missing icon by putting it everywhere: fifty instances on
the webshop page alone. Round 2 was the correction, plus the part of the book the
site had not taken at all — how a SETT page is actually *built*. Round 3 is
below, under "Round 3".

The layer lives in **one file**, `assets/brand.css`, loaded **last** on the two
catalogue pages. Because `app.css` and `chrome.css` are almost entirely
token-driven, redefining their variables from one place re-tints both design
systems at once, and the component overrides sit on top of that. Nothing in the
file changes behaviour: no layout JS measures, no element JS queries, no state.
Removing the one `<link>` returns each page to its unbranded layout.

Every rule cites the brandbook page it comes from.

### The `--blob-*` radii are gone

`--blob-1` … `--blob-4` were four invented `border-radius` values whose own
comment admitted they were taken from the Mortex tabletops "not from the SETT
bean icon". Everything that used them is square now (04.02), or carries the
numeral. The tokens are set to `0` rather than deleted, so any rule still
referencing them squares off instead of breaking.

### Type is the brandbook's now

An earlier version of this file recorded a deliberate departure from 03.02:
`--font-display` was Poppins, "cross-page consistency chosen over that one point
of fidelity". That departure is over. `assets/brand.css` loads **PT Serif** (the
real face — 03.02 names it and it is on Google Fonts under its own name),
**Libre Franklin** for Franklin Gothic URW and **Mulish** for Avenir. The two
licensed faces get their closest free cousins, and the stacks name the real ones
first, so a machine that has them uses them. Neither catalogue page requests
Poppins.

03.01 names five roles and gives each an *Opmaak*; they had all been set at one
weight, which is why the pages read flat:

| Role | The book says | On the site |
|---|---|---|
| Koppen | "Grootste tekst, **vaak vetgedrukt**" | Franklin Demi (600) — they were 500 |
| Subtitels | "Iets groter dan de broodtekst, kan licht vetgedrukt zijn" | 600 at 1.02–1.2rem |
| Broodtekst | "Gemiddelde grootte, **normaal** (niet vetgedrukt)" | Mulish 400 |
| Voetnoot | "**Kleiner** dan de broodtekst, maar nog steeds goed leesbaar" | .85rem / 400 on meta and captions |
| Citaat | "**Kan schuin worden weergegeven**" | PT Serif italic |

The one thing that stays light is the **baseline spread** (01.05) at 300 — that
is a different device from a Kop, and 05.09 sets it light. Both spread voices
are in use and both are light, never bold: Franklin Light for the grotesk
statements, PT Serif Regular for the serif one. Setting the spreads at 700 was
the single biggest reason the first version did not read as the book.

### 05.01: the hero is inverted

The book's own website page sets the statement in **black on open white** and
stacks the photograph underneath it. The webshop hero did the opposite — white
type over a scrim on moving footage. It is the 05.01 structure now: a white
`.sett-statement` field carrying the folio numeral, the rotated spine, the
justified statement and the lede, followed by a full-bleed `.sett-plate` holding
the film. Nothing sits on top of a picture, so the plate carries no scrim.

### The part of the book the site had not taken: how a page is built

Round 1 took the book's *palette, type and devices*. What it had not taken was
the book's **architecture**, which is the thing that actually makes a page look
like SETT. Four rules, visible on all 32 pages:

**1. The margin column and the folio.** Every page is a narrow left column —
running head, the two-digit folio, the caption — then a single vertical hairline,
then the content. Above 1180px the composition is a two-column grid, the numeral
and the caption sit in the margin, the hairline runs between them and the body.
Below 1180px there is no margin to give away, so it stacks — which is what the
book's own narrow formats (05.02, 05.05, 05.09) do.

**2. Sections are numbered, not marked.** The bean is gone from the section
heads; each carries `01`, `02`, `03`… in the light grotesk, on one CSS counter
per page. A heading already numbered by a mark of its own opts out with
`.has-own-number`, or the row shows two competing numbering schemes.

**3. Nothing is centred.** There is not one centred element in the brandbook.

**4. Type is never set over a photograph.** 05.01 stacks the statement *above*
the picture, 05.07 puts the photograph in the top rectangle and the type on the
field beneath, and every 05.09 tile does one or the other, never both in one
frame. The PDP tutorial caption was the last violation and the worst reading on
the site at 4.82:1 against the brightest pixel it covered; it is a 05.07 poster
now and 21:1 on white.

### 02.02 / 02.03: one accent per composition

02.03 is easy to misread as "these colours are ugly". Put it beside 02.02 and it
is the same six pieces with a **second accent introduced into each**: pink type
on a beige field, blue on green, blue on pink. The rule it teaches is *one tint
per composition* — type on a tint is black, white, or that tint's own tonal step,
never another accent.

A *set* of objects each in its own single tint is fine and is what the book does
on 05.02 and 05.05, so the product grid still cycles beige/blue/pink/green card
by card. The check runs in the verifier: every rendered text node is compared
against its own resolved ground, and any brand accent sitting on a *different*
brand accent is reported. Zero.

### The brandbook is bilingual, and so is the site

This looked like a decision and turned out not to be one. The brandbook is a
**Dutch document with English baselines**, consistently, on every page:

- Body copy, captions, section titles — Dutch.
- Every baseline on 01.05, 01.06, 02.02, 05.01, 05.07 and 05.09 — English.
  *"SETT THE TABLE FOR UNFORGETTABLE MOMENTS."*, *"THE PRODUCT IS THE RESULT.
  THE MOMENT IS THE REASON."*, *"NOT MADE TO BUY. MADE TO CREATE."*

So the split is the book's own, and the site follows it: **display baselines in
English, everything a customer has to read or act on in Dutch.** Product names,
prices, filters, buttons, delivery copy and the FAQ are untouched. An earlier
version had translated the baselines into Dutch on the reasoning that a Dutch
page wants a Dutch line; that was translating away the device.

Each English run carries `lang="en"` inside the `lang="nl-BE"` document, so a
screen reader switches voice instead of reading English through a Dutch
synthesiser. There are exactly two, both on `webshop.html`.

The two used carry no brand name, so they read correctly on a diy-atelier page.
The third, "SETT THE TABLE FOR UNFORGETTABLE MOMENTS.", is deliberately not used
— see the brand note below.

## Round 3 — the two catalogue pages, again

Round 2 left the brandbook's architecture on exactly one composition per page:
the statement field. Everything below it sat in a plain centred container with
the caption inline above the heading, which is a web layout, not a SETT page.
And the product page had had no composition pass at all — it was the original
PDP with the brand layer's colour and type over it.

### The margin column is the whole page now, not just the hero

`.sett-margin` is the book's architecture as a reusable wrapper: a narrow left
column carrying the folio numeral and the caption, one vertical hairline, then
the content. It goes **inside** the padded container rather than on it, because
the hairline is placed as a percentage and has to resolve against the same box
the grid columns do.

It is on the webshop's beige band, and on all four sections of the PDP. The
numerals run down the same x on every section of a page now — measured at 1440
the webshop's three are at 63px, 64px and 64px — which is the thing that makes a
stack of sections read as one document rather than as a stack of components.

Two details worth recording:

- **The hairline is absolute, not a grid item.** A grid pseudo set to
  `grid-row: 1 / -1` spans only the *explicit* grid, which is one row when every
  row is implicit, so it would stop under the first block. `.sett-statement-inner`
  solves this the other way round — its children are known, so its rows are
  enumerated — but a general wrapper cannot enumerate them.
- **The catalogue's head is flush left, and that is the same alignment.** The
  margin column starts at the container's left edge, so its numeral sits at
  exactly the x a flush-left numeral does. What differs is the *body*: the two
  sections above it have a body beside the margin, so their content moves into
  column 2. The catalogue's body is its own two-column filter-and-grid layout
  running full width beneath, and putting that in column 2 costs it a product
  column (four across becomes three). A heading indented 286px over a flush-left
  toolbar reads as a mistake rather than as a device, so the head is flush with
  the body it heads and carries no rule — a hairline the height of the head alone
  is a tick mark, not the book's page rule.

### The catalogue is a numbered chapter

Its heading was `sr-only`, so the page's sequence ran 01, 02, then jumped to the
closing duo — the main chapter of the page was the one thing the book's numbering
did not reach. It carries `03`, the caption "33 pakketten" and a visible
heading now, and the duo is `04`.

### The three category posters share their edges

04.01 and 04.02 set photography as a **tight** grid — rectangles butted together
with no gutter — and 02.02's duo makes the same point about a photograph against
a flat field. The three posters were separate cards with a 16px gap floating on
white, which is the one arrangement neither page makes. The hover lift went with
the gap: a shared edge that opens by 4px on hover is not a shared edge, and the
book has no motion in it. The photograph still answers the pointer with its own
slow zoom, bounded by the rectangle.

### The measure was tuned against the approved page, not guessed

A `.spread` line's measure *is* the device: too wide and the word gaps stop
reading as gaps and start reading as columns. The webshop hero — the composition
the client signed off — was measured in the browser, and the new line was tuned
to the same fill. Ink width as a percentage of its measure:

| Line | Measure | Fill |
|---|---|---|
| `webshop` hero (the reference) | 600 (`.spread-narrow`) | 56% · 71% · 60% |
| `product` closing field | 900 (`.pdp-close-line`) | 57% · 65% |

### The wordmark is in the palette — on the brandbook half

`img/logo.png` was the last off-brandbook colour on the site: a raster in the
superseded `#fd8b11` with `#333138` lettering, on an opaque white box.

It is now **two files**. `img/logo.png` is untouched and stays with the replica
half, where every accent is `#fd8b11` and a `#c75433` wordmark would clash.
`img/logo-brand.png` is the same artwork remapped to **`#c75433`** (02.01 Oranje)
and **`#000000`** (02.01 Zwart), with the white box made transparent so it can
sit on any field — and that is what the two brandbook pages load.

The alpha was recovered per pixel rather than the file being re-inked flat: for
`p = a·ink + (1−a)·white`, `a = (255−p)/(255−ink)` on the channel with the most
headroom, so the antialiased edges stay smooth instead of fringing. Solid pixels
come back as exactly `#c75433` and `#000000` — verified by counting them. A copy
of the untouched original sits outside the publish root at
`../img-originals/logo-fd8b11-original.png`.

It is still a raster and still wants the real vector.

### Colour: the brand orange replaced the legacy orange

`#fd8b11` is not in the brandbook. On the brandbook half it is gone entirely and
`#c75433` (02.01) is the only orange. There is no hard-coded colour left in the
markup of either catalogue page.

**Buttons are black, not orange.** White on `#c75433` measures **4.43:1** and
misses AA for a 12.5px label by a hair. The alternatives were to darken the
orange off-palette — which an earlier version did, to `#a8451f` — or to grow the
label out of the book's caption scale. Black is the book's own primary, it clears
21:1, and it leaves orange free to do what the book actually uses it for: the
mark. Hover inverts to the white sheet, 21:1 the other way round.

### Verified, not assumed

Run in headless Chromium against `webshop.html` and `product.html` (three
different products, so the colourway tints and both product types are covered) at
1600 / 1440 / 1280 / 1180 / 1100 / 1024 / 900 / 768 / 600 / 390 / 320 — 1180 and
1100 are where the margin column engages and disengages.

**Zero issues on both pages.**

- **No horizontal overflow** at any width.
- **No `.spread` line overflow.** A `.spread` line is `white-space: nowrap`, so a
  measure narrower than its words overflows *inside* the line box without
  widening it — comparing box edges reports 0px. The test is scroll size vs
  client size along the **inline** axis, which for the duo's rotated line is the
  page's vertical axis, not its horizontal one. Testing `scrollWidth` on a
  `writing-mode: vertical-rl` element reports a false 8px failure on every duo
  line; that is what the first run of this check did.
- **One `<h1>` per page, `alt` on every image, no console errors, no broken
  images.**
- **Every text element meets AA against its own ground**, resolved by walking up
  for the first real background rather than assuming one; large text held to
  3:1, everything else to 4.5:1. This caught one real failure introduced by this
  round — the margin-column caption at `--muted` on 02.01 green measures
  **3.32:1** at 11.2px. On a tint the caption is full ink now (7.4:1), which is
  the rule section 9 already applied to `.muted` and `.subtle` inside a band.
- **No text is set over a photograph anywhere on either page.**
- **02.03: no composition mixes two accents.** Zero.
- **The icon is counted, not eyeballed:** 3 on the webshop, 2 on the PDP.
- Tonal display tones still measure at least 3:1 on their own field.
- **The behaviour was driven, not assumed.** Category-tile filtering (33 → 8),
  search, "Lees meer", the quantity stepper, add-to-basket and the toast, and the
  colourway variant switch all still work, with no page errors.

One thing full-page screenshots show that users never do: the `.toast` is
`position: fixed; bottom: -100px` when hidden, and it is an empty element with a
black background and 14px of padding. Chromium composites fixed elements into a
full-page capture at their viewport position, so it appears as a stray 44px black
box mid-page in screenshots. On a real viewport it is off-screen. Not a defect,
but worth knowing before someone reports it as one.

### A brand question worth raising

The brandbook is **SETT** (`WWW.SETT.DESIGN`, `info@sett.design`); the site is
**diy-atelier** (`info@diy-atelier.be`, `img/logo.png`). Both list
Tweelindenstraat, so they are the same company — but this is SETT's identity
applied to diy-atelier's content, and the two brand names coexist on the page.
Worth settling before launch: either the site becomes SETT, or the SETT-specific

### The chrome is shared, the skin is not

The header and footer are generated once, by `build.py`, for all six pages — that
is what stops the navigation drifting between the two halves. But the halves are
no longer skinned alike, so `header()` takes a `brand` flag:

| | `brand=False` (replica) | `brand=True` (webshop, product) |
|---|---|---|
| wrapper | `.logo` | `.logo.sett-lockup` |
| mark | — | the 01.03 logo-icoon beside the wordmark |
| wordmark | `img/logo.png` — `#fd8b11` on white | `img/logo-brand.png` — `#c75433` / `#000000`, transparent |

Both branches emit the **same links, in the same order, with the same aria**, so
only the mark and the wordmark file differ. `sync_chrome(..., brand=True)` is what
the two catalogue pages are built with.

### What is dead in `brand.css` now

Measured, not estimated: every selector in the file was run against both
catalogue pages in a real browser, with state pseudo-classes (`:hover`,
`:focus-within`, `[aria-pressed]`, …) normalised away so they are not miscounted
as dead.

**107 of 280 base selectors match nothing.** They are almost all
replica-page components — `.video-cta`, `.quote`, `.cols3`, `.col-icon`,
`.masonry`, `.lede`, `.prod-*`, `.section-head`, `.tut-card`, the unused `.band-*`
and `.sett-field-*` tints — plus the `.sett-wm` watermark family, which is
deliberately unused: it is the "don't overuse the logo-icoon" answer, kept
because the placement is sanctioned by the book and may be wanted on one field
later.

They are **inert, not broken** — CSS that matches nothing costs a parse and
nothing else. They have been left in place deliberately, because they are also
exactly what would be needed if the replica half is ever brought under the brand
layer. Stripping them is a clean follow-up; it is not a fix.

### Why `chrome.css`

`app.css` and `site.css` both define `.site-header`, `.btn`, `.section`, `body`
and `:root`, so the catalogue cannot simply load both. `assets/chrome.css`
restates the replica header, footer and cookie bar with every rule scoped under
`.site-header` / `.site-footer` / `.cookie`, and is loaded **after** `app.css`.
`assets/brand.css` then loads after that and skins all three.

One specificity trap worth recording: `chrome.css` scopes
`.site-header .logo { display: block }` at (0,2,0), which outranks a bare
`.sett-lockup` — the icon stacked above the wordmark on the two catalogue pages
and sat beside it on the four replica ones. The lockup rule is scoped to match.

## Product art was matted in the file

The 34 product photos (`av-*`, `eh-*`, `hb-*`, `rv-*`, `sh-*`, `*-carpet-*`,
`test-title`) shipped as 800x800 canvases with the actual photograph inset as a
rounded-corner card surrounded by white padding — roughly 113px top and bottom
plus 14px at the sides on the tables, and 155/70px on the carpets. No CSS can
fix that: the gutter is baked in, so it read as a border on every card and tile
however the boxes were aligned.

All 34 are now cropped to their own content box (10px of the margin kept, since
it varies a few pixels per file). Originals are in `../img-originals/`, outside
the publish root. Filenames are unchanged, so no markup moved.

The 10px of margin kept by that pass still leaves the card's rounded corners
faintly visible, which matters on a tile the size of a category card. So the
Mortex tile has its own asset: **`img/cat-tafels.jpg`**, cut from
`../img-originals/eh-offwhite.jpg` at the strict content box minus a further
14px per side, which clears the corner radius entirely — verified at zero
near-white pixels on all four edges. It is a dedicated tile asset rather than a
product photo, so re-cropping the catalogue art can never change the tile.

They are no longer square, so the hardcoded `width="800" height="800"` came off
the `<img>` tags in `catalog.js` and `product.js` — `.card-media` reserves the
box with `aspect-ratio: 1/1` and the image covers it, so a fixed square hint was
simply a false intrinsic size. Re-crop with the same detection if new art
arrives matted the same way.

## PDP stage centring

`.pdp-stage` sizes itself with `aspect-ratio: 4/3` and frames the art with
padding in the selected colourway. The media used `width/height: 100%` as a grid
item, but a percentage height against a grid area is not dependably definite —
the browser fell back to `auto`, the image took its own intrinsic ratio and
overflowed the bottom padding. The frame was therefore even on three sides and
short on the fourth, and it got worse the taller the art (12px on the tables).
It only became visible once the product photos were de-matted and stopped being
square.

The media is now positioned against the stage with explicit `calc` sizes, since
percentages on an absolutely positioned box resolve against the containing
block's padding box, which `aspect-ratio` has already made definite. `inset`
alone is not enough: `width: auto` on a **replaced** element means its intrinsic
width, not the offsets, so the image goes full-bleed. Padding lives in one place
as `--stage-pad` so the frame and the offsets cannot drift.

Verified at 32px on all four sides for all 8 carpets and the tables, at 16px on
mobile, and for the video slot.

## The 100vw scrollbar trap

`.band` used the classic full-bleed recipe — `width: 100vw` with
`margin-inline: calc(50% - 50vw)`. **`100vw` counts the scrollbar.** On any
desktop browser with space-taking scrollbars (Windows Chrome, Edge, Firefox) the
band came out ~15px wider than the content box and the negative margin pushed
half of that past each edge, giving 8px of horizontal page scroll.

It is invisible under test: **headless Chrome uses overlay scrollbars**, so
`100vw == clientWidth` and every automated check passed. Reproducing it needs
`chromium.launch({ headless: false })`, which reports `scrollbar 15px` and the
8px overflow. Any future overflow check must run headed to be worth anything.

Bands are direct children of `<main>`, which nothing constrains, so
`width: auto` already fills the width — no viewport units needed. Keep it that
way: a band nested inside `.container` would no longer bleed.

Guard: grep the stylesheets for `width: … 100vw` before shipping. Verified 0
overflow at 1440 / 1280 / 1024 / 768 / 390 on all pages, headed.
