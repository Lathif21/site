# Atelier DIY — static site

Six pages, built from two sources that now live in one site:

- **Replica pages** — a faithful rebuild of four pages of `staging.diy-atelier.be`.
  **The design is unchanged** — colours, type scale, spacing, radii and layout are
  reproduced from the supplied screenshots, not reinterpreted.
- **Catalogue pages** — the SETT redesign of the webshop, which *does* reinterpret
  the design.

The two halves keep their own stylesheets and their own type. No page loads both.

## Pages

| File | Screen | Stylesheet | Source |
|---|---|---|---|
| `index.html` | Overzicht (homepage) | `assets/site.css` | generated by `build.py` |
| `hoe-werkt-het.html` | Hoe werkt het? | `assets/site.css` | generated by `build.py` |
| `realisaties.html` | Realisaties | `assets/site.css` | generated by `build.py` |
| `tutorials.html` | Tutorials | `assets/site.css` | generated by `build.py` |
| `webshop.html` | Catalogue — 33 pakketten | `app.css` + `chrome.css` | body hand-authored, chrome generated |
| `product.html` | Product detail (`?id=`) | `assets/app.css` | hand-authored |

`build.py` writes the four replica pages whole. For `webshop.html` it only
rewrites the header and footer, in place, between these markers:

```html
<!-- chrome:header -->  …generated…  <!-- /chrome:header -->
<!-- chrome:footer -->  …generated…  <!-- /chrome:footer -->
```

Everything outside the markers is left alone, so the catalogue body stays
hand-authored while the chrome can never drift from the replica pages. Re-run
`python build.py` after any change to `NAV`, `header()` or `FOOTER`. The sync is
idempotent — running it twice is a no-op.

`product.html` is still fully hand-authored and still carries the old chrome.

### Why `chrome.css`

`app.css` and `site.css` both define `.site-header`, `.btn`, `.section`, `body`
and `:root`, so the catalogue cannot simply load both. `assets/chrome.css`
restates the replica header, footer and cookie bar with every rule scoped under
`.site-header` / `.site-footer` / `.cookie`, and is loaded **after** `app.css`.
Nothing in it reaches the catalogue body — the footer CTA is `.site-footer .btn`
so `app.css`'s `.btn` is untouched. Its values are copied from `site.css`:
change them there first, then mirror.

## Run / deploy

Nothing to build. Open `index.html`, or:

```
python3 -m http.server 8000        # local
netlify deploy --dir=. --prod      # or drag this folder onto app.netlify.com/drop
```

`build.py` regenerates the four replica `.html` files from shared partials so the
header, footer and cookie bar can't drift apart. Edit `build.py`, run
`python3 build.py`. If you'd rather hand-edit the HTML directly, just delete
`build.py` — the pages are complete standalone files.

## Three things to replace before this goes anywhere real

**1. Typography is a best-guess match.** The live site uses a geometric sans with a
single-storey `a` and round dots. **Poppins** (Google Fonts) is the closest free
match and is what's loaded here — but I identified it by eye from a screenshot, not
from the CSS. If you can tell me the real family, it's a one-line change in
`assets/site.css`.

**2. Hero photos are cropped, not the originals.** The headlines are baked into the
screenshots, so to render them as real HTML text I had to crop each hero down to a
region of the photo that carries no text:

- `img/ov-hero.jpg` — the right-hand slice of the hero photo
- `img/hw-hero.jpg` — the full-width strip *below* the "Hoe werkt het?" headline

Both read as the same scene but are more zoomed than the original. Drop the real
photo files into `img/` under the same names and the framing is fixed instantly —
nothing else needs to change.

Every other image is a direct crop and sits at roughly the resolution the 1440px
screenshots allowed, so they are soft on a retina display. `img/logo.png` is the
same story — swap in the real SVG when you have it.

**3. Placeholder content that must be filled in:**

- **FAQ answers.** Filled in — all 10 questions carry the client's copy, held as
  `(vraag, antwoord)` pairs in the `FAQ` list in `build.py`.
- **Tutorial videos.** `tu-vid1` is filled in — a 2.5s silent screen recording of
  the admin panel, encoded to `video/tu-vid1.mp4` (H.264) + `.webm` (VP9) at
  1280x794/30fps, with `img/tu-vid1.jpg` as a matching frame-0 poster. The master
  lives outside the publish root at `../video-masters/tu-vid1-master.mov`.
  `tu-vid2` is still a placeholder — see `video/README.txt` for the recipe.

  Note that `tu-vid1` shows an internal admin screen and a logged-in employee
  name. Confirm that is intended before this goes public.
- **Cookie bar** stores the choice in `sessionStorage`. It sets no cookies and
  blocks nothing — replace with your real consent script.

## What was added, not copied

Everything at 1440px is a reproduction. Below 1024px the screenshots gave me
nothing to copy, so the responsive behaviour is my interpretation:

- Nav collapses to a burger menu at &lt;1024px
- Three-column grids → two columns at &lt;1024px, one at &lt;720px
- `.split` step rows stack, image below text
- Masonry → single column at &lt;720px
- Hero shortens and its gradient darkens so the copy stays readable

Also added, because the screenshots couldn't show them: focus rings, a skip link,
`aria-expanded`/`aria-controls` on the accordion and burger, `alt` text on every
image, and `lang="nl"`.

Verified: no console errors, one `<h1>` per page, no heading-level skips, no
unlabelled buttons or links, no image without `alt`, and no horizontal overflow
down to 320px.

## Known cosmetic gaps

- The "Uitgelichte producten" arrows are styled but inert — the live carousel's
  behaviour isn't visible in a static screenshot.
- The three "Hoe werkt het?" icons are hand-drawn SVG approximations of the
  originals, which couldn't be extracted cleanly from a JPEG.
- Product-card meta is given its own row rather than crowded onto the title line.
  On the live site longer names shove the badges around and `3 dagen` wraps; the
  same information is here, just not colliding.

## Known gaps after the merge

- **`product.html` still has the old chrome.** It keeps the 72px Libre Franklin
  header and the one-line footer, and it has no burger — `assets/app.css:334`
  shows `.mainnav` only above 900px, so below that its nav is simply absent and
  the logo (→ Overzicht) is the only way out. Giving it the shared chrome is the
  same three steps `webshop.html` went through: add the `<!-- chrome:* -->`
  markers, link `chrome.css` and `site.js`, add a `sync_chrome("product.html",
  "webshop.html")` call.
- **The catalogue header carries a basket badge the replica header does not.**
  `header(active, cart=True)` swaps the plain cart icon for `#cartBtn` +
  `#cartCount`, which `catalog.js` requires — it reads them before the grid is
  painted, so dropping them blanks the catalogue. The replica pages pass
  `cart=False` and stay pixel-identical.
- **The catalogue footer lost its prototype disclaimer.** The old one read
  "© 2026 Atelier-DIY … — Redesignprototype, geen echte webshop."; the shared
  footer is the replica's "© 2026 Atelier-DIY. Alle rechten voorbehouden." 
- **`img/ov-hero.jpg` and `img/ov-video.jpg` are byte-identical.** `ov-video.jpg`
  is now the poster for the CTA player. Both names are kept so a real still can be
  dropped into `ov-video.jpg` without touching markup.
- **The CTA video is a dummy.** "Bekijk de video en ontdek" plays `video/ov-mortex.*`
  inline instead of navigating to Tutorials — but that file is currently a copy of
  the `tu-vid1` admin recording, not Mortex footage. Drop the real clip in under
  the same names; nothing else changes.
- **Cart is decorative on the replica pages.** Their header cart/account links are
  `href="#"`; only `webshop.html` and `product.html` have a working basket, and it
  is `sessionStorage`-backed, not a real cart.
